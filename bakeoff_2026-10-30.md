# Bake-off 1 — Vergecast 2026-10-29 (43:45, two hosts + ads), run 2026-10-30 on the server

Reference: the feed's 192 kb/s stereo MP3, downmixed to mono, 24 kHz. Neural codecs coded each 30 s segment
independently from a cold start (= the seek case). Opus 1.6.1 (`opusenc --bitrate N`, VBR, stock decode, no
neural enhancement) was encoded continuously. Units for the Bayesian bootstrap = the 88 30-s segments of this one
episode (adjacent, same hosts), so the intervals cover *this episode*, not podcasts in general.

dWER = word errors of Parakeet-CTC-1.1b on the decoded audio against Parakeet on the reference (ratio estimator,
95% BB interval). The first pass used Whisper-large-v3-turbo instead; on 30 s windows Whisper sometimes dropped half
a segment or appended the next ad (also in the reference), which made its dWER floor ~5.7% and non-monotone in
bitrate. Those results are kept in `outputs/eval/whisper/` but not used.

Paired BB vs opus_12k: P(dWER lower) = 0.98 for qwen12hz, 1.00 for mimi_q32, 0.15 for mimi_q16.
Speaker-cosine sds are all < 0.002. PESQ is known to under-score neural codecs (see the SOTA report); use it only
within a codec family. Per-codebook unigram entropy coding saves 4–6% (`outputs/eval/rates.json`).

## Decoder cost (the server Zen 5 CPU, `scripts/bench_decode.py`, 5 reps, spread < 5%)

| decoder | params | GFLOP / audio-s | RTF 1 thread | RTF 4 threads | cold 2 s decode, 1 thread |
|---|---|---|---|---|---|
| Mimi (any q) | 41 M | 5.5 | 0.070 | ~0.03 | 0.11 s |
| Qwen3-TTS-Tokenizer-12Hz | 114 M | 62 | 0.59 | 0.26 | 0.76 s |

Mimi's cost barely depends on the number of codebooks (RVQ lookup is cheap; the conv/transformer decoder dominates).

## Take-aways

- At equal intelligibility, Qwen3-12Hz (2.2 kb/s) ≈ Opus 16k and Mimi-q32 (4.4 kb/s) ≈ Opus 16–24k: about 4–8×
  smaller files than Opus for the same dWER and speaker match on this episode.
- Mimi-q16 (2.2 kb/s) ≈ Opus 12k; Mimi-q8 (1.1 kb/s) ≈ Opus 6k on words but keeps the voices far better.
- Qwen3 buys its edge over Mimi-q16 at the same bitrate with ~11× the decode compute. Mimi-q32 gets equal or better
  dWER for 2× the bits at 1/11 the compute — the better phone trade if 2 MB/hour is fine.
- Not yet tested: NeuCodec (HF-gated; needs Josh to accept terms), NanoCodec, Opus 1.6 with NoLACE/BWE decoding
  (needs a libopus built with OSCE + decoder complexity ≥ 7), Qwen3 on the phone (no mobile export yet), Josh's ears
  (`outputs/listening/index.html`: 5 × 20 s excerpts, shuffled, names hidden).

Sidecar transcript: `outputs/transcript/episode.vtt` (Whisper-large-v3-turbo, VAD, 2,088 cues, RTF 0.09 on the server).

## On the phone (Galaxy Fold 8, SM8850, Android 17; Termux over ssh, 2026-10-30)

Mimi via `litert-community/Mimi` (fp16 LiteRT, fixed 2 s graphs) and the Feb-2025 TFLite `benchmark_model`
(android_aarch64). Termux's cpuset was cores 0–1,4–5 (3.6 GHz; the 4.7 GHz prime cores excluded). That old build's
XNNPACK can't prepare `mimi_dec_tx` (DEPTHWISE_CONV_2D), so the transformer ran on reference kernels; a current
LiteRT should be faster. Don't set LD_LIBRARY_PATH=/vendor/lib64 — it breaks linking, and the GPU delegate finds
OpenCL without it.

| per 2 s chunk | GPU (OpenCL) | CPU 4 threads | CPU 1 thread |
|---|---|---|---|
| `mimi_deconly` (SEANet decoder) | 48.9 ms | 515 ms | 1,464 ms |
| `mimi_dec_tx` (8-layer transformer) | 8.8 ms (fp16-unsafe per model card) | 114 ms | 132 ms |

Recommended split (tx on CPU, conv on GPU): ~165 ms back-to-back = 12× real time. Paced at real time (one chunk
per 2 s for 10 min, 300 chunks) the cores clock down between chunks: tx 224 ms avg, conv 61 ms avg (p95 66 ms),
~285 ms per 2 s = 7× real time. One-time GPU init 2.2 s (model load, so do it before playback, not per seek).

Temperature (10 s samples; mean over phase): idle 2 min → paced load 10 min → cool 3 min.
CPU max 32.5 / 28.1 / 28.0 °C, GPU max 26.9 / 26.8 / 26.1, board (sys-therm-0) 26.2 / 26.0 / 26.5,
battery 23.1 / 22.9 / 24.2. The load phase can't be told apart from idle; the battery drifted up ~0.1 °C/min
through load *and* cool-down, i.e. not from the decode (charging/ambient unknown). No power reading:
/sys/class/power_supply is not readable from Termux. Raw logs: `outputs/phone/`.

## Native phone decoder (`phone/mimi_dec.c`, LiteRT 2.3.2, built in Termux with -mcpu=native)

Build and run recipe, library list and gotchas: `phone/README.md`. Mimi q32, the transformer on the Hexagon V81
NPU (QAIRT 2.50, JIT-compiled once and then cached) and the conv decoder on the Adreno GPU:

- Full episode flat out: 2,625 s of audio in 94 s wall, with 23 s of CPU time (user+sys).
  Per 2 s window, mean 50 ms and p95 79 ms; the GPU throttled during this long flat-out run.
- dWER 1.64% [1.32, 2.00], against 1.67% for the the server PyTorch decode (paired P(lower) = 0.62).
  Speaker cosine 0.997 and PESQ-WB 3.47, the same as the CPU-transformer phone path.
- Paced at real time for 10 min (395 windows): 57.8 ms per window (p95 63), i.e. 26× real time.
  It used 6 s of CPU time in 603 s, about 1% of one core.
- Temperatures (CPU / GPU / NSP / board / battery): idle 34.2 / 32.6 / 32.7 / 33.0 / 30.6 °C, decoding
  33.5 / 32.7 / 32.3 / 32.4 / 29.1 °C. The phone kept cooling from earlier flat-out runs while it decoded.
  Raw data is in `outputs/phone/thermal_npugpu.csv`.
